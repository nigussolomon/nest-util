nest-auth

JWT authentication with refresh token rotation, RBAC, OTP login, password reset, account verification, and assisted onboarding — ready out of the box.

🔒

JWT + Refresh Rotation

Short-lived access tokens with rotating refresh tokens and nonce validation for single-session security.

⚗

RBAC

Role-based access control with @Permissions() decorator and a pluggable permission registry.

⚡

OTP Login

One-time password login with configurable code length, cooldown, lockout, and delivery callbacks.

🔑

API Key Auth

Server-to-server authentication with named keys, per-key RBAC, expiration, and revocation.

🔑

Password Reset

Token-based password reset with configurable expiry, hashed storage, and session invalidation.

Install

We recommend using pnpm as your package manager.

pnpm add @nest-util/nest-auth@^1.4.0 @nestjs/jwt @nestjs/passport typeorm@^1.1.0 @nestjs/typeorm @nestjs/swagger class-validator bcrypt

Prerequisites

  1. TypeORM must be configured in your application.
  2. Your User entity must include:
    • identifier field (e.g. email)
    • password field (e.g. password)
    • refreshToken — hashed refresh token storage
    • accessToken — hashed access token storage
    • (Optional, for OTP) otpCodeHash, otpCodeExpiresAt, otpRequestAttempts, otpLastSentAt, otpLockedUntil
    • (Optional, for Password Reset) passwordResetTokenHash, passwordResetTokenExpiresAt
  3. Create DTOs for login, register, and refresh payloads.
auth.dto.ts
import { ApiProperty } from '@nestjs/swagger';

export class LoginDto {
  @ApiProperty({ example: 'user@example.com' })
  email!: string;

  @ApiProperty({ example: 'password123' })
  password!: string;
}

export class RefreshDto {
  @ApiProperty()
  refreshToken!: string;
}

Auth Module

Register AuthModule.forRoot() in your root module with the full configuration.

app.module.ts
import { Module } from '@nestjs/common';
import { AuthModule } from '@nest-util/nest-auth';
import { User } from './user/user.entity';
import { LoginDto, RegisterDto, RefreshDto } from './auth/auth.dto';
import { permissionRegistry } from './auth/permission-registry';

@Module({
  imports: [
    AuthModule.forRoot({
      // Entity & fields
      userEntity: User,
      identifierField: 'email',
      passkeyField: 'password',

      // JWT configuration
      jwtSecret: process.env.JWT_SECRET ?? 'super-secret-key',
      refreshTokenSecret: process.env.REFRESH_TOKEN_SECRET,
      expiresIn: '1h',
      refreshTokenExpiresIn: '7d',

      // Token storage fields on User entity
      refreshTokenField: 'refreshToken',
      accessTokenField: 'accessToken',

      // DTOs
      loginDto: LoginDto,
      registerDto: RegisterDto,
      refreshDto: RefreshDto,

      // Relations loaded during JWT validation
      relations: ['userRoles', 'userRoles.role'],

      // RBAC configuration
      rbac: {
        userRolesRelation: 'userRoles',
        rolesKey: 'userRoles',
        nestedRoleKey: 'role',
      },

      // Permission registry for @Permissions() checks
      permissionRegistry,

      // Optionally disable specific routes
      disabledRoutes: [],

      // Password reset (optional)
      passwordReset: {
        enabled: true,
        tokenLength: 64,
        tokenTtlSeconds: 3600,
        tokenField: 'passwordResetTokenHash',
        expiresAtField: 'passwordResetTokenExpiresAt',
        deliverToken: async ({ identifier, token, expiresAt }) => {
          // Send email/SMS with the reset token
          console.log(`Send reset token ${token} to ${identifier}`);
        },
      },

      // OTP login (optional)
      otp: {
        enabled: true,
        codeLength: 6,
        ttlSeconds: 300,
        cooldownSeconds: 60,
        maxAttempts: 5,
        lockSeconds: 300,
        channel: 'email',
        deliverCode: async ({ identifier, code, expiresAt }) => {
          // Send email/SMS with the OTP code
          console.log(`Send OTP code ${code} to ${identifier}`);
        },
      },
    }),
  ],
})
export class AppModule {}

Assisted Onboarding

When onboarding is enabled, an agent can create a user on behalf of an invitee using a single-purpose onboarding JWT:

Method Endpoint Description Auth
POST /auth/onboarding/start Agent starts the flow — sends an OTP to the invitee onboarding.start
POST /auth/onboarding/complete Agent enters the invitee's code — returns a single-use onboarding_token onboarding.complete
POST /auth/onboarding/user Creates the user from the onboarding attempt (runs registerHooks, sets verifiedAt) OnboardingJwtGuard

Guards

The package exports these guards and strategies:

  • JwtAuthGuard — authentication via JWT Bearer token or (when enabled) x-api-key header. Skips @Public() routes.
  • PermissionsGuard — authorization against @Permissions(...) metadata.
  • RouteDisabledGuard — blocks routes listed in disabledRoutes (403).
  • OnboardingJwtGuard — validates the single-purpose onboarding JWT (used by POST /auth/onboarding/user).
  • ApiKeyGuard — standalone API key guard; normally unnecessary because JwtAuthGuard auto-detects the API key header.
  • JwtStrategy — Passport JWT strategy with nonce validation.

Use @UseGuards(JwtAuthGuard, PermissionsGuard) to protect endpoints. Example:

profile.controller.ts
import { Controller, Get, UseGuards } from '@nestjs/common';
import {
  CurrentUser,
  JwtAuthGuard,
  Permissions,
  PermissionsGuard,
  type AuthUser,
} from '@nest-util/nest-auth';

@Controller('profile')
export class ProfileController {

  // Works with JWT Bearer token or X-API-Key header
  @Get('me')
  @UseGuards(JwtAuthGuard)
  me(@CurrentUser() user: AuthUser) {
    return user;
  }

  // Works with both API key and JWT — no ApiKeyGuard needed
  @Get('data')
  @UseGuards(JwtAuthGuard, PermissionsGuard)
  @Permissions('admin.access')
  getData(@CurrentUser() user: AuthUser) {
    return { ok: true, userId: user.id };
  }
}

Decorators

Decorator Guard Required Description
@CurrentUser() JwtAuthGuard Injects the authenticated AuthUser into the handler parameter
@Permissions('key') PermissionsGuard Requires the user to hold the specified permission
@Public() None Marks a route (or whole controller) as public — skips JWT validation
@AuthOptions() None Injects the AUTH_OPTIONS token (the resolved AuthModuleOptions)

API Key Authentication

Enable API key authentication for server-to-server requests. Each key has its own roles and permissions, independent of the user who created it.

JwtAuthGuard automatically detects the x-api-key header and delegates to ApiKeyService — no separate ApiKeyGuard needed. Just use @UseGuards(JwtAuthGuard) for both JWT and API key auth.

app.module.ts (apiKey config)
AuthModule.forRoot({
  // ... other options
  apiKey: {
    enabled: true,
    headerName: 'x-api-key',    // default
    keyPrefix: 'nuk_live_',      // default
    hashRounds: 10,              // default
  },
})

Configuration Options

Option Type Default Description
enabled boolean false Enable API key authentication
headerName string 'x-api-key' Header to read the API key from
keyPrefix string 'nuk_live_' Prefix for generated keys
hashRounds number 10 Bcrypt hash rounds for key storage

Usage

data.controller.ts
import { Controller, Get, UseGuards } from '@nestjs/common';
import {
  JwtAuthGuard,
  PermissionsGuard,
  CurrentUser,
  type AuthUser,
} from '@nest-util/nest-auth';

@Controller('data')
@UseGuards(JwtAuthGuard, PermissionsGuard)
export class DataController {

  @Get()
  findAll(@CurrentUser() user: AuthUser) {
    // user.id comes from either API key or JWT
    return this.service.findAll();
  }
}

JwtAuthGuard auto-detects the X-API-Key header — no separate ApiKeyGuard needed. Both API keys and JWT tokens work on the same endpoint with just @UseGuards(JwtAuthGuard, PermissionsGuard).

Super Admin Bypass

Configure superAdminPermission in RBAC options. Any user with this permission bypasses all @Permissions() checks and custom evaluators in PermissionsGuard.

app.module.ts (rbac config)
AuthModule.forRoot({
  // ... other options
  rbac: {
    superAdminPermission: 'admin.access',
    // ... rolesKey, nestedRoleKey, etc.
  },
})

How It Works

  1. Create a key via POST /auth/api-keys (raw key returned once)
  2. Assign roles to the key via POST /auth/api-keys/:id/roles/:roleId
  3. Send the key in the X-API-Key header
  4. JwtAuthGuard detects the header and delegates to ApiKeyService
  5. The service loads the key's user and the key's roles (not the user's own roles)
  6. @CurrentUser() resolves permissions from the key's roles

Quick Start

Get up and running in three steps.

1

Install the package

Run pnpm add @nest-util/nest-auth@^1.4.0 @nestjs/jwt @nestjs/passport typeorm@^1.1.0 @nestjs/typeorm @nestjs/swagger class-validator bcrypt and ensure TypeORM is configured with a User entity.

2

Register AuthModule

Add AuthModule.forRoot() to your root module imports with entity, secrets, and DTOs.

3

Protect endpoints

Apply JwtAuthGuard and PermissionsGuard to your controllers.

@Module({

        userRolesRelation: 'userRoles',

Password Reset

Enable token-based password reset by adding the passwordReset option to AuthModule.forRoot(). You must provide a deliverToken callback to send the reset link or token to the user.

app.module.ts (passwordReset config)
AuthModule.forRoot({
  // ... other options
  passwordReset: {
    enabled: true,
    tokenLength: 64,          // Length of the generated token
    tokenTtlSeconds: 3600,    // Token validity (1 hour)
    tokenField: 'passwordResetTokenHash',
    expiresAtField: 'passwordResetTokenExpiresAt',
    deliverToken: async ({ identifier, token, expiresAt }) => {
      // Send email/SMS with the reset token or link
      console.log(`Send reset token ${token} to ${identifier}`);
    },
  },
})

Endpoints

Method Endpoint Description
POST /auth/password-reset/request Accepts { email }. Returns success even if the user doesn't exist (prevents account enumeration).
POST /auth/password-reset/reset Accepts { token, newPassword }. Invalidates all existing sessions upon success.

OTP Login

Enable One-Time Password login by adding the otp option to AuthModule.forRoot(). You must provide a deliverCode callback.

app.module.ts (otp config)
AuthModule.forRoot({
  // ... other options
  otp: {
    enabled: true,
    codeLength: 6,
    ttlSeconds: 300,         // Code validity (5 minutes)
    cooldownSeconds: 60,     // Min time between requests
    maxAttempts: 5,           // Max failed attempts before lockout
    lockSeconds: 300,         // Lockout duration
    channel: 'email',
    deliverCode: async ({ identifier, code, expiresAt }) => {
      // Send email/SMS with the OTP code
      console.log(`Send OTP code ${code} to ${identifier}`);
    },
  },
})

Endpoints

Method Endpoint Description
POST /auth/otp/request Accepts { email }. Triggers the deliverCode callback.
POST /auth/otp/login Accepts { email, otpCode }. Validates the code and returns auth tokens.

Account Verification

Enable post-register account verification (email/phone code) by adding the verification option to AuthModule.forRoot(). When enabled, register no longer returns tokens — the user must verify first.

app.module.ts (verification config)
AuthModule.forRoot({
  // ... other options
  verification: {
    enabled: true,
    codeLength: 6,
    ttlSeconds: 600,
    cooldownSeconds: 60,
    maxAttempts: 5,
    lockSeconds: 300,
    channel: 'email',
    // Optional DB field overrides (defaults shown)
    verifiedField: 'isVerified',
    verifiedAtField: 'verifiedAt',
    codeHashField: 'verificationCodeHash',
    expiresAtField: 'verificationExpiresAt',
    attemptsField: 'verificationAttempts',
    lastSentAtField: 'verificationLastSentAt',
    lockUntilField: 'verificationLockUntil',
    inputCodeField: 'verificationCode', // DTO field for the submitted code
    deliverCode: async ({ identifier, code, expiresAt }) => {
      // Send email/SMS with the verification code
    },
  },
})

Endpoints

Method Endpoint Description
POST /auth/verify Accepts { email, code }. Verifies the account; subsequent login returns tokens.
POST /auth/verify/resend Accepts { email }. Re-sends the code (respects cooldownSeconds).

Assisted Onboarding

Enable agent-assisted onboarding so an admin/agent can create a user on behalf of an invitee. The agent confirms the invitee's email via an OTP, receives a single-purpose onboarding JWT, then creates the user with that token.

app.module.ts (onboarding config)
AuthModule.forRoot({
  // ... other options
  onboarding: {
    enabled: true,
    startDto: class extends OnboardingStartDto {},
    completeDto: class extends OnboardingCompleteDto {},
    createUserDto: class extends OnboardingCreateUserDto {},
    metadata: { channel: 'email' },
    buildDeliveryContext: async ({ attempt }) => ({ /* delivery context */ }),
    sendCode: async ({ identifier, code, expiresAt }) => {
      // Send email/SMS with the onboarding OTP
    },
  },
})

Endpoints

Method Endpoint Auth Description
POST /auth/onboarding/start onboarding.start Sends an OTP to the invitee's email/phone.
POST /auth/onboarding/complete onboarding.complete Validates the invitee's code and returns a single-use onboarding_token.
POST /auth/onboarding/user OnboardingJwtGuard Creates the user (runs registerHooks, sets verifiedAt). Throws ConflictException if the user already exists.

Register Hooks

registerHooks let you run logic around user creation, atomically with the DB transaction that inserts the user:

app.module.ts (register hooks)
AuthModule.forRoot({
  // ... other options
  registerHooks: {
    beforeRegister: async ({ email }) => {
      // Runs before the user is created (e.g. validate, enrich)
    },
    afterRegister: async ({ email, user }) => {
      // Runs after the user is created, inside the same transaction
    },
  },
})

Help Notes

  • Refresh token field: The /auth/refresh endpoint currently expects refreshToken in the request body.
  • Nonce validation: Access and refresh tokens are validated against hashed nonce values stored in the database, enabling single-session token rotation. Each refresh rotates both tokens.
  • Relations requirement: If you enable RBAC, ensure relations includes the role relations needed during JWT validation (e.g. ['userRoles', 'userRoles.role']).
  • disabledRoutes: Use disabledRoutes to hard-disable selected auth endpoints (e.g. ['register', 'otp/request']). Disabled routes return 403 Forbidden.
  • superAdminPermission: Set rbac.superAdminPermission to grant full permission bypass to super admins. Users with this permission skip all @Permissions() checks.
  • API key auto-detection: JwtAuthGuard auto-detects x-api-key header and delegates to ApiKeyService — no separate ApiKeyGuard needed.
  • Refresh token header: The refresh token is sent via the x-refresh-token header (configurable with refreshTokenHeaderName).
  • identifierFields: To allow login/register via multiple fields (e.g. email or phone), set identifierFields — it takes precedence over identifierField.
  • Defaults: expiresIn defaults to '1h', refreshTokenExpiresIn to '7d', onboardingTokenExpiresIn to '15m'.
  • RBAC evaluation: Permission resolution uses directPermissionsKey and rolePermissionsKey; requireAllPermissions toggles AND vs OR, and a custom permissionEvaluator can override the default matcher.
  • Dual auth: JWT and API key auth can be enabled simultaneously — API key calls automatically bypass JWT validation.
