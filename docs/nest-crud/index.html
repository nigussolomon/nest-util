nest-crud

CRUD scaffolding, audit logging, lifecycle hooks, status pipelines, cursor pagination, findMine, and a testing factory — all in one package.

Install

We recommend using pnpm as your package manager.

pnpm add @nest-util/nest-crud@^2.0.1 @nest-util/nest-error@^1.0.0 typeorm@^1.1.0 @nestjs/typeorm @nestjs/swagger class-validator class-transformer

Optional — for guard integration in the controller section:

pnpm add @nest-util/nest-auth@^2.0.1 @nestjs/jwt @nestjs/passport bcrypt

@nest-util/nest-error is a required peer dependency. @nest-util/nest-crud includes audit logging, lifecycle hooks, ownership enforcement, status and approval pipelines, cursor pagination, findMine, and a testing factory — all built-in.

Service

Create your resource service by extending NestCrudService:

post.service.ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { NestCrudService } from '@nest-util/nest-crud';
import { Post } from './post.entity';
import { CreatePostDto } from './create-post.dto';
import { UpdatePostDto } from './update-post.dto';

@Injectable()
export class PostService extends NestCrudService<
  Post,
  CreatePostDto,
  UpdatePostDto
> {
  constructor(@InjectRepository(Post) repository: Repository<Post>) {
    super({
      repository,
      allowedFilters: ['title'],
      allowedSortFields: ['createdAt', 'title'],
      include: ['author'],
      userOwnershipField: 'authorId',
      hooks: {
        afterCreate: {
          handler: async (ctx) => {
            // Send notifications, emit events
          },
        },
      },
    });
  }
}

Service Options

crud-service-options.interface.ts
interface CrudServiceOptions<Entity, ResponseDto> {
  repository: Repository<Entity>;
  allowedFilters?: readonly (keyof Entity)[];
  allowedSortFields?: readonly (keyof Entity)[];
  include?: readonly string[];
  relations?: {
    property: keyof Entity;
    repo: Repository<ObjectLiteral>;
    idField?: string;
  }[];
  toResponseDto?: (entity: Entity | Entity[]) => ResponseDto | ResponseDto[];
  createDtoClass?: Type<unknown>;
  updateDtoClass?: Type<unknown>;
  disabledEndpoints?: readonly CrudEndpoint[];
  cursorStrategy?: CursorStrategy;          // override auto-detection
  hooks?: CrudHooks<Entity, any, any>;      // lifecycle hooks
  transactionConfig?: TransactionConfig;    // isolation level for hooks
  userOwnershipField?: keyof Entity;        // ownership column for findMine
  findMineQuery?: (qb, userId) => void;     // custom findMine query
  enforceOwnership?: boolean;               // scope read/update/delete to owner
  ownershipBypassPermissions?: readonly string[]; // permissions that bypass ownership
  ownershipBypass?: (user: OwnershipUser) => boolean; // custom ownership bypass
  superAdminPermission?: string;            // permission that skips ownership checks
  statusPipeline?: StatusPipelineConfig<Entity>;  // status transition rules
  approvalPipeline?: ApprovalPipelineConfig;      // draft/submitted approval workflow
}

allowedSortFields readonly (keyof Entity)[] Whitelist of fields that can be sorted
include readonly string[] Relations to auto-join (eager load)

Controller

CreateNestedCrudController generates all standard endpoints with Swagger docs, audit decorators, and permission metadata.

post.controller.ts
import { Controller, UseGuards } from '@nestjs/common';
import {
  CreateNestedCrudController,
  IBaseController,
} from '@nest-util/nest-crud';
import { ApiBearerAuth, ApiTags } from '@nestjs/swagger';
import {
  JwtAuthGuard,
  PermissionsGuard,
  buildCrudPermissionsFromRegistry,
} from '@nest-util/nest-auth';

const PostCrudControllerBase = CreateNestedCrudController(
  CreatePostDto,
  UpdatePostDto,
  Post,
  {
    permissions: buildCrudPermissionsFromRegistry(permissionRegistry, {
      resource: 'posts',
    }),
    enableFindMine: true,  // enables GET /post/mine
  }
) as abstract new (service: PostService) => IBaseController<
  CreatePostDto, UpdatePostDto, Post
>;

@ApiTags('post')
@Controller('post')
@ApiBearerAuth()
@UseGuards(JwtAuthGuard, PermissionsGuard)
export class PostController extends PostCrudControllerBase {
  constructor(override readonly service: PostService) {
    super(service);
  }
}

Status Pipeline

Enforce a status field with a declared transition graph. Configure on the service:

post.service.ts (statusPipeline)
super({
  repository,
  statusPipeline: {
    field: 'status',
    initial: 'draft',
    transitions: [
      { from: 'draft', to: ['pending'] },
      { from: 'pending', to: ['approved', 'rejected'] },
      { from: 'rejected', to: ['pending'] },
      { from: 'approved', to: ['published'] },
    ],
  },
});

Transitions can also be written as a plain map, and edges may carry a permission and/or an action:

post.service.ts (transitions forms)
transitions: {
  draft: ['pending'],
  pending: ['approved', 'rejected'],
},
// or with a required permission / side-effect action per edge:
// transitions: [
//   { from: 'pending', to: ['approved'], permission: 'posts.approve' },
//   { from: 'approved', to: ['published'], action: async (ctx) => { /* notify */ } },
// ]

Actions

Run side effects when a status transitions. Each edge may define an action, and the pipeline may define a global onTransition that runs after every transition:

post.service.ts (actions)
statusPipeline: {
  field: 'status',
  initial: 'draft',
  transitions: [
    { from: 'draft', to: ['pending'] },
    { from: 'pending', to: ['approved', 'rejected'] },
    {
      from: 'approved',
      to: ['published'],
      action: async ({ id, entity }) => {
        await notifySubscribers(id);
      },
    },
  ],
  onTransition: async ({ id, from, to, user }) => {
    await auditLog.write({ id, from, to, user: user?.id });
  },
},

The action context is { id, entity, from, to, user } — entity is the saved entity (status already reflects the new value), from/to are the previous and new status values, and user is the authenticated user who triggered the transition.

Behavior

  • Create: status is auto-set to initial (after validation, before beforeCreate). Explicit statuses are rejected (400) unless listed in allowCreateStatuses (initial is always allowed).
  • Update: a status change must be a registered edge (from → to); otherwise a 400 with the allowed target statuses is returned. Edges with a permission require the caller to hold it (403 via the existing ownership/permission resolver).
  • POST /:id/status: dedicated endpoint mirroring update semantics (404 when no pipeline is configured or the endpoint is disabled). Body: { "status": "approved" }.
  • Hooks: status validation runs after beforeUpdate hooks, so hook-driven mutations are also validated.
  • Actions: run after the transition is saved (edge action first, then global onTransition) and are awaited. They never fire for same-status no-ops, missing status fields, or rejected transitions.

Permission gating: grant posts.changeStatus (or map the action via endpointActions when building permissions) and use @ApiBearerAuth + PermissionsGuard as in the controller section.

Approval Pipeline

An approval workflow for created records: draft → submitted → approved / rejected, with modification requests and resubmission in between. Every create also writes an approval_statuses row in the same transaction.

post.service.ts (approvalPipeline)
super({
  repository,
  approvalPipeline: {
    initialStatus: 'draft',   // or 'submitted' (no explicit submit step)
    permissions: {
      submit: 'posts.submit',
      approve: 'posts.approve',
      reject: 'posts.reject',
      requestModification: 'posts.update',
      resubmit: 'posts.update',
    },
    visibleStatuses: ['approved'],
  },
});

Endpoints

  • POST /:id/approval/submit — draft → submitted
  • GET /:id/approval — current status + full modification history
  • POST /:id/approval/approve / reject — from submitted/resubmitted; records decidedBy/decidedAt
  • POST /:id/approval/request-modification — body { modifications: [{ field, wantedValue, note? }], note? }; captures each field's live value (relations auto-loaded, no include needed) plus a SHA-256 hash into an immutable history row
  • POST /:id/approval/resubmit — modification_requested → resubmitted

Resubmit Check (resubmitCheck)

wantedValue is a suggestion, not a requirement. To stop users from blindly pressing resubmit, configure resubmitCheck: each captured value is hashed (SHA-256 of canonical JSON) at request time, and at resubmit time the live field is hashed the same way. An unchanged field blocks the resubmit with 400 CRUD_APPROVAL_RESUBMIT_NOT_SATISFIED, listing the untouched fields.

resubmit check config
approvalPipeline: {
  resubmitCheck: {
    mode: 'all',            // default 'all' | 'any' (at least one changed)
    ignoreFields: ['tags'],   // advisory fields that don't gate resubmission
    customChecker: async ({ modifications, satisfied, entity }) => {
      return satisfied.every((s) => s.satisfied);
    },
  },
},
  • Relation fields work without configuring include — loaded automatically for capture and check.
  • Key order, undefined/null, and Date forms are normalized by canonical hashing, so jsonb round-trips don't cause false positives. Collections compare as unordered sets — reordering rows alone isn't a change.
  • Legacy rows without hashes fall back to deep equality against the stored currentValue.
  • Editing a field back to its exact original value reads as "unchanged" — only current-vs-snapshot is known.

Lifecycle Hooks

Intercept any CRUD operation with before/after hooks — with optional transaction wrapping.

hooks.interface.ts
interface CrudHooks<TEntity, TCreateDto, TUpdateDto> {
  beforeCreate?: CrudHookConfig<{ payload: TCreateDto }>;
  afterCreate?:  CrudHookConfig<{ entity: TEntity; payload: TCreateDto }>;
  beforeUpdate?: CrudHookConfig<{ payload: TUpdateDto; entity: TEntity; id: number }>;
  afterUpdate?:  CrudHookConfig<{ entity: TEntity; payload: TUpdateDto; id: number }>;
  beforeRemove?: CrudHookConfig<{ entity: TEntity; id: number }>;
  afterRemove?:  CrudHookConfig<{ id: number; deleted: boolean }>;
  beforeFindOne?: CrudHookConfig<{ id: number }>;
  afterFindOne?:  CrudHookConfig<{ entity: TEntity; id: number }>;
}

interface CrudHookConfig<TContext> {
  handler: (context: TContext) => Promise<any> | any;
  transaction?: boolean;  // wraps in DB transaction
}

interface TransactionConfig {
  isolationLevel?: 'READ UNCOMMITTED' | 'READ COMMITTED'
    | 'REPEATABLE READ' | 'SERIALIZABLE';
  timeout?: number;
}

Available Hooks

  • beforeCreate / afterCreate
  • beforeUpdate / afterUpdate
  • beforeRemove / afterRemove
  • beforeFindOne / afterFindOne

Transaction Config

Set transaction: true on any hook to wrap it inside a database transaction. Configure isolation level and timeout via transactionConfig in your service options.

Configuring Hooks

post.service.ts (hooks)
super({
  repository,
  hooks: {
    beforeCreate: {
      handler: async (ctx) => {
        // validate, transform
      },
      transaction: true,  // runs inside a DB transaction
    },
    afterCreate: {
      handler: async (ctx) => {
        // send events, notify
      },
    },
  },
  transactionConfig: {
    isolationLevel: 'READ COMMITTED',
  },
});

Cursor Pagination

Pass ?cursor=<opaque> to GET / for efficient keyset pagination on large datasets.

How It Works

  • Integer PKs: Uses id > cursor — fast index scan
  • UUID PKs: Uses composite (createdAt, id) cursors for stable ordering
  • Cursors are opaque base64url-encoded values — clients should not parse them

Usage Examples

cursor-pagination.sh
# First page
GET /posts?limit=10

# Next page — use the cursor from the previous response
GET /posts?cursor=eyJpZCI6MTB9&limit=10

# With total count (adds a DB COUNT query)
GET /posts?cursor=eyJpZCI6MTB9&limit=10&includeTotal=true

Cursor Helpers

Low-level utilities are exported for custom pagination logic:

Helper Description
base64UrlEncode(payload) / base64UrlDecode(raw) Encode/decode opaque base64url cursors
decodeCursor(raw, strategy) Validate and decode a cursor against a strategy
applyCursorFilter(qb, decoded, strategy, dir) Mutate a TypeORM SelectQueryBuilder with the cursor predicate
buildNextCursor(entities, strategy) Build the next cursor from the last page of results
detectCursorStrategy(repo) Auto-detect integer vs uuid from the repository PK metadata

Strategies: { type: 'integer' } or { type: 'uuid', timestampColumn }.

findMine

Retrieve user-scoped records via GET /resource/mine. Requires enableFindMine: true on the controller and userOwnershipField or findMineQuery on the service.

Simple Column Match

post.service.ts (findMine)
super({
  repository,
  userOwnershipField: 'authorId',
});

Custom Query Builder

post.service.ts (findMineQuery)
super({
  repository,
  findMineQuery: (qb, userId) => {
    qb.where('e.authorId = :userId', { userId })
      .orWhere('e.id IN (SELECT postId FROM post_collaborators WHERE userId = :userId)', { userId });
  },
});

Filtering

Filtering uses the filter[field_operator]=value query parameter format.

Example

filtering.sh
# Exact match
GET /posts?filter[title_eq]=Hello

# Contains
GET /posts?filter[title_cont]=lo

# Greater than or equal
GET /posts?filter[createdAt_gte]=2024-01-01

# Multiple filters

Audit Events

The AuditInterceptor emits typed events for every CRUD operation via @nestjs/event-emitter. Plug in your own handlers to send events to PostHog, Sentry, or any analytics platform.

Setup

app.module.ts
import { AuditEventModule, ConsoleHandler } from '@nest-util/nest-crud';

@Module({
  imports: [
    AuditEventModule.forRoot({
      handlers: [
        new ConsoleHandler(),   // built-in: logs to stdout
      ],
      include: ['crud.*'],      // only CRUD events
      exclude: [],                // optional exclusions
    }),
  ],
})

CRUD Events

Event When Key Fields
crud.<entity>.create.success Entity created entityId, body, response
crud.<entity>.create.error Create failed body, error
crud.<entity>.update.success Entity updated entityId, body, response
crud.<entity>.update.error Update failed entityId, body, error
crud.<entity>.delete.success Entity deleted entityId
crud.<entity>.delete.error Delete failed entityId, error
crud.<entity>.findAll.success List query query, response count
crud.<entity>.findOne.success Single entity fetched entityId, response
crud.<entity>.findMine.success User-scoped list userId, query

Each success event has a matching .error variant emitted on failure.

Custom Handler

posthog.handler.ts
import { AuditEventHandler, AuditEvent } from '@nest-util/nest-crud';
import { PostHog } from 'posthog-node';

export class PostHogHandler implements AuditEventHandler {
  private client: PostHog;

  constructor(apiKey: string) {
    this.client = new PostHog(apiKey);
  }

  handle(event: AuditEvent): void {
    this.client.capture({
      distinctId: String(event.userId ?? 'anonymous'),
      event: event.action,
      properties: {
        entity: event.entity,
        entityId: event.entityId,
        ...event.metadata,
      },
    });
  }
}

DB-Backed Audit Trail

Register NestCrudModule to get a persistent audit_logs table and the AuditService for page- and cursor-based queries.

app.module.ts
import { TypeOrmModule } from '@nestjs/typeorm';
import { NestCrudModule, AuditLogEntity } from '@nest-util/nest-crud';

@Module({
  imports: [
    TypeOrmModule.forFeature([AuditLogEntity]),
    NestCrudModule, // provides AuditService
  ],
})
export class AppModule {}

AuditLogEntity columns: id, tenantId, action, entity, entityId, userId, metadata (jsonb), ip, userAgent, createdAt.

audit usage
import { AuditService } from '@nest-util/nest-crud';

constructor(private readonly auditService: AuditService) {}

async track() {
  await this.auditService.logEntityAction('export.run', 'report', '42', {
    userId: 'u1',
    metadata: { rows: 100 },
  });

  // page-based
  const { data, meta } = await this.auditService.findAll({ entity: 'report', page: 1, limit: 20 });

  // cursor-based
  const { data, meta } = await this.auditService.findAllWithCursor({ limit: 20, includeTotal: true });
}

AuditService methods: log(input), logEntityAction(action, entity, entityId?, options?), findAll({ entity?, userId?, startDate?, endDate?, page?, limit? }), findAllWithCursor({ cursor?, limit?, includeTotal?, entity?, userId?, startDate?, endDate? }).

Help Notes

  • disabledEndpoints: Use disabledEndpoints in service options to hide generated routes without rewriting controllers.
  • relations: The relations option lets you resolve propertyId payload fields into related entities automatically.
  • findAuditLogs: If findAuditLogs is not implemented in your service, /auditlogs returns not found by design.
  • changeStatus: POST /:id/status returns 404 unless a statusPipeline is configured on the service and the endpoint is not disabled.
  • findMine requirements: findMine returns 404 unless enableFindMine: true is set on the controller and userOwnershipField or findMineQuery is configured on the service.
  • Express query parser: Set app.set('query parser', 'extended') in bootstrap for deep object query parsing (required for filter syntax).
