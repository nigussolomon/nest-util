nest-error

Standardized, localized, generic error responses for every package in the nest-util ecosystem.

🔑

Stable Error Keys

Every error carries a machine-readable errorKey. Branch on a code, not an English string.

🌐

Localized Messages

Messages resolve from a language map via Accept-Language with a configurable default.

🛡

No Leakage

SQL, stack traces, and raw user input are stripped from the client response by default.

Install

We recommend using pnpm as your package manager.

pnpm add @nest-util/nest-error

Peer dependencies:

pnpm add @nestjs/common @nestjs/core express

@nest-util/nest-error is a required peer dependency of every other nest-util package. Register LocalizationModule.forRoot(...) once to render the standardized body.

Quick Start

Register the module once, globally, in your root module. It wires the I18nService, LangResolverService, and a global LocalizedExceptionFilter.

app.module.ts
import { LocalizationModule } from '@nest-util/nest-error';
import errorMessages from './config/error-messages.json';

@Module({
  imports: [
    LocalizationModule.forRoot({
      messages: errorMessages, // { [lang]: { [errorKey]: 'template' } }
      defaultLang: 'en',
      supportedLangs: ['en', 'am'],
      debug: process.env.NODE_ENV !== 'production',
    }),
  ],
})
export class AppModule {}

Language is resolved from Accept-Language (clamped to supportedLangs), or from the x-lang header when allowHeaderOverride is true.

Throwing Errors

Use keyed() instead of new HttpException(...). It returns the matching native NestJS exception class, so the HTTP status and exception type are unchanged — existing toThrow(...) assertions keep passing.

some.service.ts
import { keyed, ErrorKey, HttpStatus } from '@nest-util/nest-error';

if (!user) {
  throw keyed(HttpStatus.NOT_FOUND, ErrorKey.AUTH_USER_NOT_FOUND);
}

throw keyed(
  HttpStatus.BAD_REQUEST,
  ErrorKey.AUTH_PASSWORD_WEAK,
  { minLength: 8 },            // interpolated into the message (safe values only)
  { attemptId: '...' },        // redacted from the client unless debug
);

Custom app errors

custom-error.ts
import { AppError, ErrorKey, HttpStatus } from '@nest-util/nest-error';

throw new AppError(
  HttpStatus.CONFLICT,
  ErrorKey.AUTH_ROLE_ALREADY_EXISTS
);

params are string-interpolated into the translated message. safeDetails are never sent to the client unless debug is enabled, and must never contain user input or secrets.

Response Body

With LocalizationModule registered, every error renders as:

error response
{
  "status": "error",
  "code": "AUTH_USER_NOT_FOUND",
  "message": "The requested user was not found",
  "statusCode": 404,
  "details": null,
  "timestamp": "2026-08-22T12:00:00.000Z",
  "path": "/users/42"
}
  • code — the stable ErrorKey (e.g. AUTH_USER_NOT_FOUND).
  • message — the localized, generic message for code.
  • details — populated only when debug is enabled.

Fallback codes for non-keyed exceptions

TypeORM QueryFailedError unique violations map to DB_DUPLICATE_ENTRY (HTTP 422) with no SQL leaked; other database errors map to DB_QUERY_FAILED.

Localization

LocalizationModule.forRoot({ messages }) deep-merges your JSON over the library's built-in defaultMessages, so you only override what you need.

error-messages.json
{
  "en": {
    "AUTH_USER_NOT_FOUND": "The requested user was not found",
    "AUTH_PASSWORD_WEAK": "Your password must be at least {minLength} characters"
  },
  "am": {
    "AUTH_USER_NOT_FOUND": "መጠቀሚያው አልተገኘም",
    "AUTH_PASSWORD_WEAK": "የይለፍ ቃልዎ ቢያንም {minLength} ፊደላት ሊሆን አለበት"
  }
}

Services

I18nService

Translate an errorKey with {placeholder} interpolation:

i18n.service.ts
import { I18nService, ErrorKey } from '@nest-util/nest-error';

constructor(private readonly i18n: I18nService) {}

const msg = this.i18n.translate(
  ErrorKey.AUTH_USER_NOT_FOUND,
  undefined,
  'am'
);

LangResolverService

Resolve the active language for a request from x-lang, Accept-Language, or the default:

lang-resolver.ts
import { LangResolverService } from '@nest-util/nest-error';

constructor(private readonly langs: LangResolverService) {}

const lang = this.langs.resolve(request);

Error Keys

The ErrorKey enum is the single source of truth for every standardized code. Keys are namespaced UPPER_SNAKE and stable across releases.

Namespace Examples
CRUD_* CRUD_RESOURCE_NOT_FOUND, CRUD_FORBIDDEN, CRUD_INVALID_FILTER, CRUD_APPROVAL_INVALID_TRANSITION
AUTH_* AUTH_INVALID_CREDENTIALS, AUTH_UNAUTHORIZED, AUTH_OTP_EXPIRED, AUTH_API_KEY_REVOKED
NOTIFY_* NOTIFY_FCM_NOT_CONFIGURED, NOTIFY_EMAIL_DELIVERY_FAILED
PAYMENT_* PAYMENT_CHECKOUT_FAILED, PAYMENT_REFUND_NOT_FOUND
FILE_* FILE_NOT_FOUND, FILE_TOO_LARGE, FILE_INVALID_TYPE
Generic / DB DB_DUPLICATE_ENTRY, DB_QUERY_FAILED, VALIDATION_FAILED, INTERNAL_ERROR

Adding new error keys

  1. Add the key to the ErrorKey enum in libs/nest-error/src/lib/constants/error-keys.ts.
  2. Add the English default to default-messages.ts.
  3. Add translations in your app's error-messages.json.
  4. Throw with keyed(HttpStatus.X, ErrorKey.YOUR_KEY).

Help Notes

  • Required peer: every other nest-util package imports @nest-util/nest-error at runtime, so install it in any project using those packages.
  • Register once: add LocalizationModule.forRoot(...) in the root module. Without it, thrown errors carry the key but render through Nest's default filter instead of the standardized body.
  • Assert on codes, not text: English wording is generic and localizable, so branch on body.code rather than parsing messages.
  • Keep debug off in production: it re-enables details/params/stack in the client response.
  • Reuse keys: prefer an existing ErrorKey over adding a new one when the semantics match.
