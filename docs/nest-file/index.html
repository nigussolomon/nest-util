nest-file

S3-compatible file management with presigned URL uploads, image processing, thumbnail generation, and TypeORM metadata tracking.

⚡

Presigned URL Uploads

Files go directly to S3 — they never touch your server. Works with AWS S3, MinIO, DigitalOcean Spaces, and any S3-compatible provider.

📸

Image Processing

Automatic resize, compress, format conversion (WebP, AVIF, JPEG, PNG), and EXIF stripping on upload confirmation.

📷

Thumbnails

Generate configurable thumbnail sizes automatically during upload processing.

🗃

Metadata Tracking

TypeORM entity stores file name, size, dimensions, compression ratio, user ownership, and custom metadata.

🛡

Zero-Boilerplate Controller

Module auto-registers all endpoints. No controller class needed — just configure and go.

Install

We recommend using pnpm as your package manager.

pnpm add @nest-util/nest-file@^1.0.0 sharp

Peer dependencies:

pnpm add @nestjs/common @nestjs/swagger @nestjs/typeorm class-validator typeorm

Optional — for RBAC permissions:

pnpm add @nest-util/nest-auth

Module

Register NestFileModule.forRoot() in your root module. Endpoints are available immediately — no controller class needed.

app.module.ts
import { NestFileModule } from '@nest-util/nest-file';

@Module({
  imports: [
    NestFileModule.forRoot({
      s3: {
        region: process.env.AWS_REGION,
        bucket: process.env.S3_BUCKET,
        accessKeyId: process.env.AWS_ACCESS_KEY_ID,
        secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
        publicUrl: 'https://my-bucket.s3.amazonaws.com',
      },
      controller: {
        permissions: {
          upload: 'files.create',
          download: 'files.read',
          list: 'files.read',
          remove: 'files.delete',
        },
      },
    }),
  ],
})
export class AppModule {}

Async Configuration

app.module.ts (async)
import { NestFileModule } from '@nest-util/nest-file';
import { ConfigService } from '@nestjs/config';

NestFileModule.forRootAsync({
  useFactory: (config: ConfigService) => ({
    s3: {
      region: config.getOrThrow('AWS_REGION'),
      bucket: config.getOrThrow('S3_BUCKET'),
      accessKeyId: config.getOrThrow('AWS_ACCESS_KEY_ID'),
      secretAccessKey: config.getOrThrow('AWS_SECRET_ACCESS_KEY'),
    },
  }),
  inject: [ConfigService],
})

Controller

The module auto-registers a file controller by default — no manual class needed. Configure it via the controller option.

app.module.ts (controller config)
NestFileModule.forRoot({
  s3: { /* ... */ },
  controller: {
    path: 'files',              // default
    permissions: {
      upload: 'files.create',
      download: 'files.read',
      list: 'files.read',
      remove: 'files.delete',
    },
  },
})

Custom Controller

For custom routing, disable the auto-registered controller and use CreateFileController():

files.controller.ts
import { Controller } from '@nestjs/common';
import { CreateFileController, FileService } from '@nest-util/nest-file';

const FileBase = CreateFileController({
  permissions: {
    upload: 'files.create',
    download: 'files.read',
    list: 'files.read',
    remove: 'files.delete',
  },
});

@Controller('custom-files')
export class FilesController extends FileBase {
  constructor(override readonly fileService: FileService) {
    super(fileService);
  }
}

Upload Flow

Files are uploaded directly to S3 via presigned URLs — they never touch your server.

client-upload.ts
// Step 1: Request upload URL
const { uploadUrl, key, fileId } = await fetch('/files/upload-url', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    fileName: 'photo.jpg',
    mimeType: 'image/jpeg',
  }),
}).then(r => r.json());

// Step 2: Upload directly to S3
await fetch(uploadUrl, {
  method: 'PUT',
  headers: { 'Content-Type': 'image/jpeg' },
  body: file,
});

// Step 3: Confirm upload — triggers image processing
const fileEntity = await fetch('/files/confirm', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ fileId, key }),
}).then(r => r.json());

Image Processing

When a file with an image/* MIME type is confirmed, the processor automatically:

  • Resizes — fits within maxWidth x maxHeight without enlarging
  • Converts — outputs as WebP, AVIF, JPEG, or PNG
  • Compresses — applies quality setting for optimal file size
  • Strips EXIF — removes metadata for privacy and smaller files

If the compressed version is smaller than the original, it replaces the uploaded file in S3.

Processing Pipeline

image-pipeline.ts
// Sharp-based pipeline (runs on confirm)
sharp(buffer)
  .rotate()                    // auto-rotate + strip EXIF
  .resize({
    width: 2048,
    height: 2048,
    fit: 'inside',
    withoutEnlargement: true,
  })
  .webp({ quality: 80 })      // or .avif(), .jpeg(), .png()
  .toBuffer();

Thumbnails

Configure thumbnail sizes in the module options. Each size generates a separate file stored alongside the original.

thumbnail config
thumbnails: {
  enabled: true,
  sizes: [
    { width: 150, height: 150, suffix: 'thumb' },
    { width: 400, height: 400, suffix: 'medium' },
  ],
}

Thumbnails are stored as WebP with cover fit mode. The first thumbnail URL is saved to FileEntity.thumbnailUrl.

Testing

Use the testing entry point for mock factories and reusable test suites.

file.service.spec.ts
import { Test, TestingModule } from '@nestjs/testing';
import { getRepositoryToken } from '@nestjs/typeorm';
import {
  FileService,
  FileEntity,
  createMockRepository,
  createMockS3Service,
  createMockImageProcessor,
  createMockThumbnailService,
} from '@nest-util/nest-file/testing';

const module: TestingModule = await Test.createTestingModule({
  providers: [
    FileService,
    { provide: getRepositoryToken(FileEntity), useValue: createMockRepository() },
    { provide: S3Service, useValue: createMockS3Service() },
    { provide: ImageProcessorService, useValue: createMockImageProcessor() },
    { provide: ThumbnailService, useValue: createMockThumbnailService() },
  ],
}).compile();
