nest-notify

FCM push and SMTP email notifications with device-token persistence and per-user history.

🔔

FCM Push

Firebase Cloud Messaging delivery in batches of 500 with automatic dead-token pruning.

✉

SMTP Email

nodemailer-powered email with host/port config or a pre-built transport, and default sender.

📋

Zero-Boilerplate Controller

Module auto-registers a guarded controller. No controller class needed — just configure and go.

Install

We recommend using pnpm as your package manager. firebase-admin and nodemailer are bundled as regular dependencies.

pnpm add @nest-util/nest-notify @nest-util/nest-error

Peer dependencies:

pnpm add @nestjs/common @nestjs/swagger @nestjs/typeorm class-validator typeorm

Required — for JwtAuthGuard, PermissionsGuard, and @CurrentUser():

pnpm add @nest-util/nest-auth

@nest-util/nest-error is required. Register LocalizationModule.forRoot(...) once for consistent error responses.

Module

Register NestNotifyModule.forRoot() in your root module. Endpoints are available immediately — no controller class needed.

app.module.ts
import { NestNotifyModule } from '@nest-util/nest-notify';

@Module({
  imports: [
    AuthModule.forRoot({ /* ... */ }),  // required: guards + @CurrentUser()
    NestNotifyModule.forRoot({
      fcm: {
        enabled: true,
        projectId: process.env.FIREBASE_PROJECT_ID,
        clientEmail: process.env.FIREBASE_CLIENT_EMAIL,
        privateKey: process.env.FIREBASE_PRIVATE_KEY,
      },
      smtp: {
        enabled: true,
        host: process.env.SMTP_HOST,
        port: 587,
        user: process.env.SMTP_USER,
        pass: process.env.SMTP_PASS,
        from: { name: 'My App', address: 'no-reply@example.com' },
      },
      controller: {
        path: 'notify',
        permissions: {
          devices: 'notify.devices',
          push: 'notify.push',
          email: 'notify.email',
          history: 'notify.history',
        },
      },
    }),
  ],
})
export class AppModule {}

Async Configuration

app.module.ts (async)
import { NestNotifyModule } from '@nest-util/nest-notify';
import { ConfigService } from '@nestjs/config';

NestNotifyModule.forRootAsync({
  useFactory: (config: ConfigService) => ({
    fcm: {
      enabled: true,
      projectId: config.getOrThrow('FIREBASE_PROJECT_ID'),
      clientEmail: config.getOrThrow('FIREBASE_CLIENT_EMAIL'),
      privateKey: config.getOrThrow('FIREBASE_PRIVATE_KEY'),
    },
    smtp: {
      enabled: true,
      host: config.getOrThrow('SMTP_HOST'),
      port: Number(config.getOrThrow('SMTP_PORT')),
      from: { address: config.getOrThrow('SMTP_FROM') },
    },
  }),
  inject: [ConfigService],
})

Configuration Options

Option Type Description
fcm.enabled boolean Enable push notifications. Default: false
fcm.app App Pre-initialized firebase-admin App (alternative to service-account fields)
fcm.projectId string Firebase project ID (service account)
fcm.clientEmail string Service-account client email
fcm.privateKey string Service-account private key
smtp.enabled boolean Enable email notifications. Default: false
smtp.transport Transporter Pre-built nodemailer transport (alternative to host/port)
smtp.host string SMTP host
smtp.port number SMTP port
smtp.secure boolean Use TLS (port 465). Default: false
smtp.user string SMTP username
smtp.pass string SMTP password
smtp.from { name?, address } Default sender. Required when SMTP is enabled via host/port
controller.enable boolean Auto-register controller. Default: true
controller.path string Controller route path. Default: 'notify'
controller.permissions object RBAC permissions for devices, push, email, history endpoints

Guardrails

  • fcm.enabled: true throws at construction unless fcm.app OR (fcm.projectId + fcm.clientEmail + fcm.privateKey) is provided.
  • smtp.enabled: true throws at construction unless smtp.transport OR (smtp.host + smtp.port + smtp.from.address) is provided.

Controller

The module auto-registers a notify controller by default — no manual class needed. It is guarded with JwtAuthGuard + PermissionsGuard. Configure it via the controller option.

Custom Controller

For custom routing, disable the auto-registered controller and use CreateNotifyController():

notify.controller.ts
import { Controller } from '@nestjs/common';
import { CreateNotifyController, NotifyService } from '@nest-util/nest-notify';

const NotifyBase = CreateNotifyController({
  permissions: {
    devices: 'notify.devices',
    push: 'notify.push',
    email: 'notify.email',
    history: 'notify.history',
  },
});

@Controller('custom-notify')
export class NotifyController extends NotifyBase {
  constructor(override readonly notifyService: NotifyService) {
    super(notifyService);
  }
}

Endpoints

One controller factory produces a complete REST API. All endpoints are guarded with JwtAuthGuard + PermissionsGuard.

Method Endpoint Description Permission Key
POST /notify/devices Register an FCM device token { token, platform, deviceId? } devices
GET /notify/devices List the current user's device tokens devices
DELETE /notify/devices Unregister a device token devices
POST /notify/push Send a push { title, body, userId?, imageUrl?, clickAction?, data? } push
POST /notify/email Send an email { to, subject, text?, html?, cc?, bcc?, replyTo?, userId? } email
GET /notify/history Query notification history { channel?, page?, limit? } (current user only) history

push and email default to the authenticated user when userId is omitted.

Notify Service

The NotifyService is exported and can be injected anywhere:

Method Description
registerDeviceToken(userId, token, platform, deviceId?)Upsert a device token for a user
unregisterDeviceToken(userId, token)Delete a user's device token
listDeviceTokens(userId)List a user's device tokens
push(userId, payload)Send a push to all of a user's tokens; records history; prunes dead tokens
pushToToken(token, payload)Fire-and-forget push to a single token
email(payload, userId?)Send an email; records history
getNotifications({ userId, channel?, page?, limit? })Paginated notification history

push returns { successCount, failureCount, results: [{ token, success, code? }] }. FCM messages are sent in batches of 500.

Dead-Token Pruning

After a batch send, responses carrying dead-token codes are collected and removed from the device_tokens table:

  • messaging/registration-token-not-registered
  • messaging/invalid-registration-token
  • messaging/invalid-argument
  • messaging/mismatched-credential

Testing

Unit tests use mocked firebase-admin and nodemailer modules — no network calls.

jest.mock('firebase-admin/app', () => ({
  initializeApp: jest.fn(),
  getApps: jest.fn(() => []),
  cert: jest.fn((o) => ({ __credential: o })),
}));
jest.mock('firebase-admin/messaging', () => ({
  getMessaging: jest.fn(),
}));

Run the suite with nx test nest-notify.
