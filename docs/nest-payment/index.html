nest-payment

Provider-agnostic payment library with checkout sessions, subscriptions, refunds, webhook handling, reconciliation, and idempotency.

⚡

Provider-Agnostic

No SDK bundled. Implement the PaymentProvider interface for any gateway — Chapa, Stripe, PayPal, etc.

🔗

Webhook-First

Webhook/callback is the source of truth for payment status. Not the API response.

🔄

Reconciliation

Stale pending/processing payments checked against provider automatically. Configurable interval.

🔒

Idempotency

DB constraints on provider IDs, idempotency keys, and forward-only status transitions.

💰

Checkout, Subscriptions, Refunds

Full payment lifecycle. Provider reports what's supported — library adapts.

Install

We recommend using pnpm as your package manager.

pnpm add @nest-util/nest-payment

Peer dependencies:

pnpm add @nestjs/common @nestjs/swagger @nestjs/typeorm class-validator class-transformer typeorm

Optional — for @CurrentUser() integration:

pnpm add @nest-util/nest-auth

Module

Register NestPaymentModule.forRoot() with your provider and entities.

app.module.ts
import { NestPaymentModule } from '@nest-util/nest-payment';

@Module({
  imports: [
    NestPaymentModule.forRoot({
      providers: [new ChapaProvider()],  // array of providers
      entities: [Payment, Subscription, Refund],
      webhook: {
        enable: true,
        path: 'webhook',           // default
        rawBody: true,             // default
        deduplicate: true,         // default
        deduplicationTtlMs: 300_000, // 5 min window
      },
      onWebhook: async (event, rawBody) => {
        // Optional hook after each processed webhook event
      },
      onReconciliationMismatch: async (payment, providerStatus) => {
        // Optional hook when reconciliation finds a mismatch
      },
      controller: {
        path: 'payments',
        permissions: {
          checkout: 'payments.create',
          list: 'payments.read',
          refund: 'payments.refund',
          subscriptions: 'payments.subscriptions',
          reconcile: 'payments.reconcile',
        },
      },
    }),
  ],
})
export class AppModule {}

Async Configuration

app.module.ts (async)
import { NestPaymentModule } from '@nest-util/nest-payment';
import { ConfigService } from '@nestjs/config';

NestPaymentModule.forRootAsync({
  useFactory: (config: ConfigService) => ({
    providers: [new ChapaProvider()],
    entities: [Payment, Subscription, Refund],
    webhook: { enable: true, path: 'webhook' },
  }),
  inject: [ConfigService],
})

Configuration Options

Option Type Description
providers PaymentProvider[] Your payment gateway implementations (array)
entities Entity[] TypeORM entities for Payment, Subscription, Refund
webhook.enable boolean Enable webhook endpoint (default: true)
webhook.path string Webhook route segment (default: 'webhook')
webhook.rawBody boolean Use raw body for signature verification (default: true)
webhook.deduplicate boolean In-memory event dedup (default: true)
webhook.deduplicationTtlMs number Dedup window (default: 300_000 = 5 min)
reconciliation.enable boolean Enable stale payment reconciliation (default: true)
reconciliation.staleAfterMs number Stale threshold in ms (default: 600_000 = 10 min)
onWebhook fn Called after each processed webhook event
onReconciliationMismatch fn Called when reconciliation finds a mismatch
controller.path string Controller route path (default: 'payments')
controller.permissions object RBAC permissions for checkout, refund, subscription
controller.enable boolean Auto-register controller (default: true)

The module is registered with global: true, so PaymentService, SubscriptionService, RefundService, and the PAYMENT_OPTIONS token are available app-wide without re-importing.

Provider Interface

Implement PaymentProvider for your gateway. The library calls your methods — no SDK is bundled.

chapa.provider.ts
import { PaymentProvider } from '@nest-util/nest-payment';

export class ChapaProvider implements PaymentProvider {
  readonly id = 'chapa';

  async createCheckoutSession(input) {
    const response = await chapa.initialize({
      amount: input.amount,
      currency: input.currency,
      callback_url: input.callbackUrl,
      tx_ref: `tx_${Date.now()}_${randomBytes(8).toString('hex')}`,
    });
    return {
      providerReference: response.tx_ref,
      checkoutUrl: response.checkout_url,
    };
  }

  async parseWebhookEvent(rawBody, headers) {
    const payload = JSON.parse(rawBody.toString());
    return {
      provider: this.id,
      type: 'chapa.checkout.completed',
      providerPaymentId: payload.tx_ref,
      status: 'succeeded',
    };
  }

  async getPaymentStatus(providerPaymentId) {
    const result = await chapa.verify(providerPaymentId);
    return result.status === 'success' ? 'succeeded' : 'pending';
  }
}

Interface Methods

Method Required Description
id Yes Unique provider identifier (e.g. 'stripe', 'chapa')
createCheckoutSession(params) Yes Create a checkout session; returns CheckoutSessionResult
parseWebhookEvent(rawBody, headers) Yes Parse raw webhook/callback body into a normalized WebhookEvent
verifyWebhookSignature(rawBody, headers) No Return true if the signature is valid; the endpoint rejects invalid ones
getPaymentStatus(id) No Query provider for actual status (used by reconciliation)
createRefund(params) No Issue a full or partial refund (refund endpoint enabled when present)
createSubscription(params) No Create a recurring subscription (enabled when present)
cancelSubscription(id) No Cancel an active subscription (enabled when present)

Optional methods are feature-detected — implement them to enable the corresponding feature. Feature gates like supportsSubscriptions are not part of the interface.

Webhooks & Callbacks

The webhook/callback is the source of truth for payment status — not the API response. A single endpoint, POST /payments/webhook/:provider, handles both provider webhooks and Chapa-style callback_url redirects.

Flow

webhook processing
// 1. Signature verified (if provider implements verifyWebhookSignature)
// 2. Raw body parsed via provider.parseWebhookEvent → WebhookEvent
// 3. Deduplicated in-memory (TTL window, default 5 min)
// 4. Dispatched: paymentService.handleWebhook(event)
//                 subscriptionService.handleWebhook(event)
//                 refundService.handleWebhook(event)
// 5. onWebhook(event, rawBody) callback fires
POST /payments/webhook/chapa   // Chapa callback_url
POST /payments/webhook/stripe  // Stripe signed webhook

In-Memory Deduplication

Webhook events are deduplicated in-memory within the configurable TTL window (default 5 min). This prevents duplicate processing from retried webhooks.

Reconciliation

Stale payments in pending, processing, or succeeded status are automatically checked against the provider via getPaymentStatus(). Payments in failed, refunded, or canceled are skipped.

reconciliation config
NestPaymentModule.forRoot({
  // ...
  reconciliation: {
    enable: true,
    staleAfterMs: 600_000, // 10 min
  },
})

A bulk endpoint (POST /payments/reconcile) reconciles all stale payments, and a per-ID endpoint (POST /payments/reconcile/:id) targets a single payment. Orphaned payments (never reached the provider) are automatically marked as failed.

Idempotency

Three layers prevent duplicate charges and inconsistent state:

  • DB constraints — unique index on (provider, providerPaymentId) and (provider, providerSubscriptionId)
  • Idempotency key — idempotencyKey field stored with each payment
  • Status guards — forward-only transitions (backward transitions silently ignored)

Status Transitions

Status transitions are validated in the service layer. Backward transitions are ignored (idempotent).

Services

PaymentService

  • createCheckout(userId, dto) → { payment, checkoutUrl?, error? } — creates a pending record first, then calls the provider; on provider failure the payment stays pending with an error (never marked failed). Idempotent when idempotencyKey is supplied.
  • handleWebhook(event) → PaymentEntity — applies forward-only status transitions, or creates a record for unknown payments.
  • findOne(id) / findByProviderPaymentId(provider, providerPaymentId)
  • findAll({ page?, limit?, orderBy?, orderDirection?, provider?, status? }) → { data, meta }
  • findMine(userId, query?) → { data, meta } — user-scoped
  • reconcilePayment(id) → PaymentEntity — orphaned payments (no providerPaymentId) are marked failed
  • reconcileStalePayments({ staleAfterMs? }) → { checked, updated, failed }
  • getProvider(providerId) → PaymentProvider

SubscriptionService

  • create(userId, dto) → { subscription, error? }
  • cancel(subscriptionId) → SubscriptionEntity — requires provider cancelSubscription
  • handleWebhook(event) → SubscriptionEntity | null
  • findOne(id) / findAll(query?) / findMine(userId, query?)

RefundService

  • create(userId, dto) → { refund, error? } — requires provider createRefund
  • handleWebhook(event) → RefundEntity | null
  • findOne(id) / findByPaymentId(paymentId) / findAll(query?)
